# Excel-мерджер файлов Яндекс Маршрутов (route planning)
Настольный инструмент для сотрудника, который готовит результаты маршрутизации к анализу: склеивает файлы результатов Яндекс Маршрутов в единый файл с исходной структурой листов.
## Бизнес-контекст
В процессе планирования маршрутов адресная программа по региону загружается в Яндекс Маршруты не единым файлом, а порезанной на части (как правило, на шесть) — так расчёт маршрутов строится точнее. На выходе получается набор файлов результатов по каждому региону. Для анализа — сравнения исходной адресной программы с результатом Яндекса по каждому региону — части нужно сначала склеить воедино.
Раньше склейка выполнялась вручную. Инструмент убирает ручное объединение: сотрудник выбирает файлы в GUI и получает один итоговый файл.
## Режимы склейки
### 1. Обычная склейка (несколько файлов)
Объединяет несколько файлов результатов в один.
- Обрабатывает фиксированный набор листов: `visit order`, `dropped locations`, `visit duration`, `visits per week`, `employees`, `data`, `routes_metrics`.
- Для листов с переменной структурой (`visit order`, `visit duration`, `visits per week`) строит единую шапку: базовым берётся файл с наибольшим числом колонок, недостающие в других файлах колонки дополняются пустыми значениями.
- Предупреждает, если лист отсутствует в файле или если структуры колонок различаются: пользователь получает список расхождений, а не молчаливо битый результат.
- Результат — `merged_result.xlsx` в папке первого выбранного файла; шапка начинается со второй строки, как в исходных файлах.
### 2. Взаимоисключающая склейка (два файла)
Для случая, когда основной и дополнительный файлы покрывают взаимоисключающие множества сотрудников и точек.
- Строки с пересекающимися ключами (`employee` или `id` в зависимости от листа) удаляются из основного файла перед объединением.
- Бизнес-правило для `dropped locations`: из основного файла удаляются точки, которые присутствуют в `visit order` дополнительного файла — если точка построена в дополнительном файле, она не считается выпавшей.
- Проверяет наличие всех обязательных листов в обоих файлах и предупреждает о различиях структуры колонок.
- Результат — `merged_result.xlsx` в папке основного файла.
### 3. Простая склейка импорта (одинаковые файлы)
Склейка импортных файлов одинаковой структуры для загрузки в систему.
- Проверяет, что все листы первого файла присутствуют в каждом следующем.
- Лист `options` (глобальные параметры) берётся только из первого файла — чтобы не дублировать настройки.
- Результат — `import_merged_result.xlsx` в папке первого выбранного файла.
## Технические детали
- Python 3, `pandas` + `openpyxl`, GUI на `tkinter`.
- Обработка файлов идёт в отдельном потоке: интерфейс не замерзает, ход обработки виден по прогресс-бару.
- Имена листов сопоставляются без учёта регистра и пробелов по краям — защита от «человеческих» расхождений в названиях.
- Пустые строки удаляются автоматически.
- Расхождения структур между файлами не ломают склейку молча: пользователь получает предупреждение со списком расхождений.

## Роль в проекте
Инструмент — один из элементов автоматизации проекта переноса планирования маршрутов на Яндекс Маршруты. Вместе с перестройкой самого процесса проект снизил трудозатраты на подготовку маршрутизации с 6 сотрудников до 1 и срок подготовки с 2 недель до 2 дней.
